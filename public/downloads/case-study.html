COMMERCE OPERATIONS EXPLORER

Commerce analysis, with an inspectable database

By Bronson Hatch · independent project · release 0.1.0

Explore historical commerce activity through a working PostgreSQL application and a separate Power BI analytical model. The business interface answers questions about orders, merchandise, sellers, and deliveries; engineering details remain available for inspection.

Business problem

Commerce records live at different grains. An order can have several items, payment records, and reviews. Joining all of them directly can inflate money totals and misstate delivery or review rates. This project organizes those records into a relational core and a reporting model with explicit definitions.

What the application does

Filter by purchase period and customer region. Inspect order items and payments without multiplying records. Compare seller/category merchandise value and regional delivery outcomes. Open a query panel to inspect the actual SQL template and separately bound parameters.

Data and correctness

The complete source contains 99,441 orders. Delivered merchandise value is R$13,221,498.11, independently reconstructed from original CSV prices using decimal arithmetic. The source has 814 repeated review IDs; the model retains separate source records and applies a deterministic latest-review rule. Review text stays outside the public application views.

Checks cover source totals, 150 seeded per-order calculations, filtered totals, delivery eligibility, fact-table grains, permission restrictions and rollback after a constraint failure. Merchandise value excludes freight and does not represent platform revenue or profit.

Architecture

Original files → preserved raw records → typed relational tables → order, order-item and payment facts → restricted API views → React application and Power BI. Foreign keys and appropriate exact-decimal fields enforce the model. Runtime credentials only permit approved reads.

Security and operations

Parameterized queries, structural allowlists, limited permissions, bounded requests, safe text rendering and browser security headers form the application controls. Injection attempts are checked against real query paths. A restored prepared-data backup must reconcile to source totals. Test coverage is described in the evidence; no universal security guarantee is made.

Limitations

Historical records cover 2016–2018, with incomplete edge months and missing attributes. Original timestamps do not establish a timezone. Delivery/review comparisons are descriptive. The project is independent and was not commissioned by Olist. Free hosting can sleep or hit quotas, and recorded benchmarks depend on their documented environment.
